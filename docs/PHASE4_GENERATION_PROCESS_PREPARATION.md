## Actual evidence / missing guarantee
Acquisition.ProbeProcess already uses ArgumentList, closed stdin, simultaneous limited reads, cancellation/deadline and root wait. Its finally skips Kill when HasExited is true, and waits without a cleanup timeout; this is not a descendant/EOF containment proof. Existing MediaProbe.TestHost/ProbeProcessTests cover arguments, nonzero exit, hang, two pipe floods and invalid UTF8, not orphaned pipe writers. Neither file is changed/reused as a public API.

Microsoft documents that Kill is asynchronous, root WaitForExit/HasExited do not establish descendant exit, and inaccessible descendants may be skipped: [Process.Kill .NET10](https://learn.microsoft.com/en-us/dotnet/api/system.diagnostics.process.kill?view=net-10.0). [WaitForExitAsync](https://learn.microsoft.com/en-us/dotnet/api/system.diagnostics.process.waitforexitasync?view=net-10.0) cancellation ends the wait, not the process. Redirected pipes require independent concurrent consumption to avoid deadlock: [RedirectStandardOutput](https://learn.microsoft.com/en-us/dotnet/api/system.diagnostics.processstartinfo.redirectstandardoutput?view=net-10.0). Requesting [ReadAsync cancellation](https://learn.microsoft.com/en-us/dotnet/api/system.io.stream.readasync?view=net-10.0) is not a hard deadline for every native operation.

## Recommendation: trusted leaf tools, fail closed on uncertain cleanup
Support only configured, audited executables/scripts that never spawn children: sequential direct FFmpeg, later an owned stdlib Python worker without subprocess/multiprocessing. This is a usage precondition, not an OS-enforced security boundary. A detached child that closes inherited pipes is not portably detectable here; root exit plus EOF must never be called a general tree-drain guarantee. Untrusted plugins, shell launchers, spawning workers and arbitrary process trees require a separate containment review (Windows jobs/Linux equivalent); no P/Invoke/dependency/daemon is proposed now.

One runner instance per owning job/session, one admitted operation and no queue. Success requires root exit0, both real EOFs and observed owned tasks under the leaf precondition. Run completion and resource release are separate. LocalReleased means owned operations/handles settled, NOT proof that arbitrary descendants are gone. Pending means an owned start/kill/read/close/wait task has not settled. Quarantined means observed contract/drain failure: reject further invocations and retain job-directory ownership even if local handles later close. Closing a pipe is not observing EOF.

## Precise API proposal — internal, review before code
- GenerationProcess(TimeProvider? clock=null, TimeSpan? drainGrace=null); RunAsync(GenerationProcessOptions options,CancellationToken caller=default) returns Task<GenerationProcessResult>; CloseAsync() returns one reusable Task<GenerationProcessCleanup>. No IAsyncDisposable that implies success after an unconfirmed drain.
- Options: absolute executable, immutable argument list, absolute working directory, execution timeout, separate stdout/stderr byte limits. Proposed defaults30s/1MiB/64KiB; maxima10min/32MiB/64KiB. Drain grace defaults2s, at most10s. Cap256args/64KiB combined text; validate lexical paths/Unicode/limits before start. No executable PATH lookup or shell, UseShellExecute=false/CreateNoWindow, redirected stdin immediately closed, simultaneous BaseStream byte readers. No UTF8/JSON parsing in this layer. Arguments/DLL/resource resolution still follow the trusted tool/OS; this is not file/network containment.
- Result: Reason, optional observed ExitCode, immutable bounded stdout/stderr on success only, Cleanup reference. Reasons: Success/Cancelled/TimedOut/Unavailable/OutputLimit/PipeFailure/NonZeroExit/DrainIncomplete/Busy/Closed/InvalidInvocation. Cleanup exposes State(LocalReleased/Pending/Quarantined) and non-faulting observable WhenLocalReleased task; the latter may remain pending and is never implicitly awaited forever. Its completion means local operations settled, not that Quarantined has cleared.
- Pre-cancel starts nothing. Until atomic outcome publication, observed-cause priority is caller cancellation > pipe output limit > pipe I/O failure > deadline > unavailable/nonzero > success. Freeze once; later cancellation does not alter a published result. Cleanup status is independent, so Cancelled+Pending cannot be mistaken for released ownership. No raw paths/argv/stderr in exception/error text; raw bytes are internal bounded data, never automatically logged.

## Control / drain policy
Start/coordinator/kill/stream-close work runs off UI and outside state locks; token callbacks only signal state, never synchronously kill or drain. Track every started task, catch/observe faults and keep a strong operation owner until release. Count retained output bytes plus fixed scratch buffers; do not claim an OS CPU/RAM/disk quota.

Execution uses a finite deadline across root wait AND both readers; root exit alone cannot publish success. After root exit, wait for real EOF only within remaining execution time and a separate finite drain grace. Stop requests trigger one best-effort tree kill while the root can still be addressed, then bounded root/reader observation and requested local cancellation/stream closure. All stop causes share that path.

If root exited while a pipe writer remains, report DrainIncomplete and quarantine; do not skip this because HasExited=true. If start/kill/dispose/read itself stalls, return Pending after the managed observation budget while an owned background tracker observes eventual settlement. Do not use unbounded WaitForExit(None) in a finally or lose tasks after a timed wait. Native calls/OS scheduling cannot be promised a hard wall-clock bound.

The runner blocks its own admission on Pending/quarantined outcomes; the future job owner must also hold next-stage/workspace deletion/publication. This runner does not delete or validate workdirs. CloseAsync closes admission first, shares existing cleanup, and returns its bounded-attempt status; it does not discard pending ownership. A later observer may mark Pending locally released, but Quarantined stays fail-closed. Do not create a fresh runner to bypass a held job lease. No automatic unquarantine/retry; external recovery/stronger containment needs separate review. Tests must distinguish local release from descendant proof.
